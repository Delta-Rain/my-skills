# 小语种译文最小改动修订

基于中英译文的改动，对应修改小语种，保持改动最小。

## 输入要求

用户需提供（缺失时主动询问，不要自行脑补）：

1. **原始中文** — 修改前的中文文案
2. **原始英文** — 与原始中文对应的英文
3. **修改后中文** — 已改好的中文
4. **修改后英文** — 与修改后中文对应的英文（如用户未提供，可基于中文推断，但最好索要）
5. **原始小语种** — 需修改的小语种当前译文，并注明语言（德/法/西/俄/日/韩等）

多条文案按条目编号成对给出。

## 工作流程

### 步骤1：对齐中英差异，输出改动分析表

逐句对比原始 vs 修改后的中文和英文，列出每一处改动：

| 位置 | 原始 | 新 | 改动类型 |
|---|---|---|---|

明确区分：标点变化、用词替换、删句/加句、语序调整、数字/奖励项变化等。

### 步骤2：判断哪些改动需要同步到小语种

**核心原则：以中文（源语言）的改动为主，英文改动作为参考。**

- ✅ **必须同步**：中文明确的删词/删句、用词替换、数字/奖励项变化、标点变化（若小语种有对应表达）
- ✅ **英文有但中文无的改动**：如 Ultimate→Deluxe 这类术语统一，需判断是否是全局术语调整。若是，同步到小语种（除非用户指定某语言保留，如俄语保留 супернабор）
- ❌ **不同步**：英文独有的句式重构、润色加词（如加 unlock/exclusive/claim your）、英文侧语序调整——这些是英文本地化润色，不是源语言改动
- ❌ **不同步**：小语种中没有对应表达的中文改动（如中文"趁现在！"→"趁现在~"，但小语种只译了"限时"没译"趁现在"）

### 步骤3：逐语言最小改动

对每门小语种：

1. 只改与中英改动对应的部分，其余**逐字保留**（包括原译的措辞、语序、标点、格式）
2. 删句后注意合并前后主谓（如删了"X是Y。她可以…"，要合并为"X可以…"）
3. 奖励列表删减时，保留剩余项的原译表达，只删被去掉的项
4. **不要**把小语种原有的签到/登录表达（如德语 Schau rein、法语 Connectez-vous、西语 Inicia sesión、俄语 Отмечайтесь）强行改成英文 Check-In——原表达已对应，保留即可
5. **不要**主动修正原文的格式问题（如缺空格、拼写小错），除非影响改动执行

### 步骤4：标注判断点

每门语言修改后，用简短 `> 改动：` 说明改了什么。遇到以下情况必须明确标注并请用户确认：

- 某改动在小语种中找不到明确对应
- 术语替换有多种可选译法
- 英文独有的改动是否需要同步存在歧义
- 用户之前对某语言有特殊决定（如"俄语保留原译文不用 deluxe"），需延续该决定

## 输出格式

```
## 改动分析
（改动分析表 + 同步/不同步判断说明）

## 修改后的小语种

### 🇩🇪 德语
**原始：** ...
**修改后：** ...
> 改动：...

### 🇫🇷 法语
...
```

## 完整案例

详见 [references/examples.md](references/examples.md)，包含5个真实案例：
1. 泳装礼包标题（去emoji + Ultimate→Deluxe）
2. 兑换码邮件（去"签到"）
3. 组合活动文案（标点+去签到+Ultimate→Deluxe，英文句式重构不同步）
4. 签到奖励列表（奖励项删减改"等其他奖励"）
5. 角色介绍（删身份背景句+合并主谓）
