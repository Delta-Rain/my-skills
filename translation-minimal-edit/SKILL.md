# 小语种译文最小改动修订

基于中英译文的改动，对应修改小语种，保持改动最小。

## 输入要求

用户需提供（缺失时主动询问，不要自行脑补）：

1. **原始中文** — 修改前的中文文案
2. **原始英文** — 与原始中文对应的英文
3. **修改后中文** — 已改好的中文
4. **修改后英文** — 与修改后中文对应的英文（如用户未提供，可基于中文推断，但最好索要）
5. **原始小语种** — 需修改的小语种当前译文，并注明语言（德/法/西/俄/日/韩等）

多条文案按条目编号成对给出。

## 工作流程

### 步骤1：对齐中英差异，输出改动分析表

逐句对比原始 vs 修改后的中文和英文，列出每一处改动：

| 位置 | 原始 | 新 | 改动类型 |
|---|---|---|---|

明确区分：标点变化、用词替换、删句/加句、语序调整、数字/奖励项变化等。

### 步骤2：判断哪些改动需要同步到小语种

**核心原则：以中文（源语言）的改动为主，英文改动作为参考。**

- ✅ **必须同步**：中文明确的删词/删句、用词替换、数字/奖励项变化、标点变化（若小语种有对应表达）
- ✅ **英文有但中文无的改动**：如 Ultimate→Deluxe 这类术语统一，需判断是否是全局术语调整。若是，同步到小语种（除非用户指定某语言保留，如俄语保留 супернабор）
- ❌ **不同步**：英文独有的句式重构、润色加词（如加 unlock/exclusive/claim your）、英文侧语序调整——这些是英文本地化润色，不是源语言改动
- ❌ **不同步**：小语种中没有对应表达的中文改动（如中文"趁现在！"→"趁现在~"，但小语种只译了"限时"没译"趁现在"）

### 步骤3：术语检查（涉及术语时强制执行）

如果改动涉及以下任何一类术语，**必须**先调用 [Glossary Translation](glossary-translation) skill 查术语表，确认标准译法后再动手修改：

- 角色名（如 残虹/Zankou、黒羽/Blackbird）
- 道具/货币名（如 环石/Annulith、捏造骰子/Fabricated Dice、方斯/Fons）
- 技能/状态名（如 浊燃/Scorch、幻境形态/Illusion form）
- 组织/头衔名（如 红字/The Scarlet Letter、特级猎人/Elite Hunter）
- 版本/活动名（如 NTE1.3、雾中朔望星回）
- 任何其他可能在术语表中有固定译法的专有名词

**执行方式：**
1. 从改动中提取所有涉及的术语（中文和英文）
2. 调用 Glossary Translation skill 的术语查询功能，检索这些术语在目标小语种中的标准译法
3. 如果术语表中有对应译法，**必须使用术语表的译法**，不要自行翻译
4. 如果术语表中没有对应译法，标注为"⚠ 术语表未收录"，请用户确认译法或补充到术语表
5. 如果改动是术语替换（如 Ultimate→Deluxe），需确认新术语在术语表中的标准译法

**注意：** 术语检查是修改前的必经步骤，不要跳过。即使看起来是简单的用词替换，也可能涉及术语表中的固定译法。

### 步骤4：逐语言最小改动

对每门小语种：

1. 只改与中英改动对应的部分，其余**逐字保留**（包括原译的措辞、语序、标点、格式）
2. 删句后注意合并前后主谓（如删了"X是Y。她可以…"，要合并为"X可以…"）
3. 奖励列表删减时，保留剩余项的原译表达，只删被去掉的项
4. 术语替换必须使用步骤3中确认的术语表标准译法
5. **不要**把小语种原有的签到/登录表达（如德语 Schau rein、法语 Connectez-vous、西语 Inicia sesión、俄语 Отмечайтесь）强行改成英文 Check-In——原表达已对应，保留即可
6. **不要**主动修正原文的格式问题（如缺空格、拼写小错），除非影响改动执行

### 步骤5：回译验证（强制执行）

修改完成后，**必须**对每门语言的修改结果做回译验证，确认改动准确无误：

1. **回译**：将修改后的小语种译文回译成中文（或英文，选择与改动更相关的语言）
2. **对比**：将回译结果与修改后的中文（或英文）目标文本逐句对比
3. **检查项**：
   - ✅ 所有应改的部分是否都改了（无漏改）
   - ✅ 改动是否准确对应中英目标（无误改、无偏差）
   - ✅ 不应改的部分是否保持原样（无过度修改）
   - ✅ 术语使用是否与术语表一致
   - ✅ 删句后语法是否通顺、主谓是否正确合并
   - ✅ 标点、格式是否与目标一致
4. **发现问题**：如果回译对比发现任何不一致，立即修正，并重新回译验证
5. **输出验证结果**：在最终输出中简要说明回译验证结果（"回译验证通过"或列出修正的问题）

**回译原则：** 回译是为了验证准确性，不是重新翻译。只需要关注改动涉及的部分，不需要对整段译文做精校。如果改动很小（如只改了一个标点），回译验证可以简化为针对性检查。

### 步骤6：标注判断点

每门语言修改后，用简短 `> 改动：` 说明改了什么。遇到以下情况必须明确标注并请用户确认：

- 某改动在小语种中找不到明确对应
- 术语替换有多种可选译法（或术语表未收录）
- 英文独有的改动是否需要同步存在歧义
- 用户之前对某语言有特殊决定（如"俄语保留原译文不用 deluxe"），需延续该决定
- 回译验证中发现的无法自行判断的问题

## 输出格式

```
## 改动分析
（改动分析表 + 同步/不同步判断说明）

## 术语检查
（如涉及术语，列出术语查询结果；如不涉及术语，说明"本次改动不涉及术语，跳过术语检查"）

## 修改后的小语种

### 🇩🇪 德语
**原始：** ...
**修改后：** ...
> 改动：...
> 回译验证：通过 / 已修正XX问题

### 🇫🇷 法语
...
```

## 完整案例

详见 [references/examples.md](references/examples.md)，包含5个真实案例：
1. 泳装礼包标题（去emoji + Ultimate→Deluxe）
2. 兑换码邮件（去"签到"）
3. 组合活动文案（标点+去签到+Ultimate→Deluxe，英文句式重构不同步）
